# legacy — 옛 실험 기록

현행 추천기(`recommender.py`, Kiwi + BM25)로 갈아타기 전에 시도했던 방식들을
기록으로 남긴다. **어느 것도 지금 코드에서 import 하지 않는다.**
지우지 않고 두는 이유는 “왜 지금 방식을 골랐는가”의 근거이기 때문이다.

## 왜 임베딩을 버렸나

KOBIS 메타데이터만으로 임베딩을 만들면 문서가 사실상 `장르 / 제작국 / 감독 / 형식`
네 낱말뿐이라, 27,852편이 15,328개의 문장으로 뭉친다. 유사도가 전부 0.9 근처에
몰려 순위가 무의미해졌다.

```
「인터스텔라」 대비 유사도  최대 0.9968 · 중앙값 0.9254
「기생충」 1위는 「마더」 유사도 1.0000 (입력 문장이 글자까지 동일)
```

무엇보다 **왜 그 영화가 추천됐는지 설명할 수 없었다.** 384차원 내적에는 근거가
없다. BM25는 겹친 낱말을 그대로 보여줄 수 있어 이쪽을 택했다.

## 벤치마크 수치에 대한 경고

`evaluate_recommenders.py`는 문서를 만들 때 `movie_text(movie)`를 기본값(metadata)
으로 호출했다. 그래서 **줄거리 벤치마크를 돌려도 TF-IDF와 BM25는 메타데이터를,
임베딩만 줄거리를 입력받았다.** `reports/plot_benchmark.md`의 TF-IDF 86.90% /
BM25 87.20%는 줄거리 성능이 아니라 메타데이터 성능이 잘못 기록된 값이다.

동일 조건(602편·동일 100질의·같은 줄거리 텍스트)으로 다시 재면 이렇게 나온다.

| 방식 | 옛 리포트 | 동일 입력으로 재측정 |
|---|---:|---:|
| TF-IDF | 86.90% | 55.70% |
| BM25 | 87.20% | 62.20% |
| 문장 임베딩 | 49.60% | 49.60% (불변) |

임베딩 수치만 변하지 않았다는 것이 곧 그것만 줄거리를 먹었다는 증거다.

## 평가 기준 자체의 한계

세 리포트 모두 정답을 “추천 영화가 기준 영화와 장르를 하나 이상 공유하는가”로
정의했다. 그런데 입력에 장르가 들어 있으므로 **자기 입력을 되맞히는 순환 지표**에
가깝다. 장르를 직접 받는 metadata 방식이 유리하고, 사건을 담은 plot 방식은
구조적으로 불리하다. 이 표들로 방식의 우열을 판정해서는 안 된다.

앞으로 평가 지표를 다시 만든다면 장르 겹침이 아닌 다른 기준이 필요하다.
